# Bell · 排课助手

面向中国普通高中「3+3」选科走班的本地排课工具。

Bell 将行政班课程、选考教学班、教师和教室安排到同一张周课表中。冲突按学生实际参加的课程检查，适用于学校已经完成分班，以及仅有学生选科、需要自动成班的两种情况。项目数据和排课结果保存在本机，核心功能无需账户或网络连接。

> 当前为 Alpha 源码版本，暂不提供可直接安装的软件包。

## 主要功能

- **导入学校数据**：支持 CSV 和 Excel `.xlsx`，可手动对应文件或工作表，查看具体表格、行列的错误提示。
- **两种成班方式**：使用学校提供的教学班与学生名单，或根据选科和班额设置生成候选教学班，再逐一排课。
- **生成与查看课表**：设置求解时限、运行模式和随机种子，支持取消；按行政班、教学班、教师、教室、学生、学科或年级查看结果。
- **保存运行历史**：保留排课参数、来源版本和结果，重新打开时复核课表，也可通过 CLI 重新导出已保存的运行。
- **管理独立方案**：将成功结果采用为新方案，直接查看各方案的课表或创建独立副本。采用方案不会改写原始导入数据，旧数据版本的方案仍可打开查看。
- **导出 Excel 和 CSV**：按班级、教师、教室、学生等对象导出完整课表。Excel 包含周课表、课程清单和来源说明，支持并行课程与连堂展示。

排课使用 Google OR-Tools CP-SAT。每份生成的课表都须经过独立的 Rust 校验器，检查学生、教师、教室、课时、连续课程和固定安排等必需约束。找不到解、超时和主动取消会分别显示，不会自动放宽约束后交付一张有冲突的课表。

## 使用流程

1. 准备学生、行政班、选科、教师、教室和课程数据。可以从 [示例数据](fixtures/small) 了解文件格式。
2. 导入 CSV 或 Excel 工作簿，确认每个文件、工作表对应的数据类型，并修正检查发现的问题。
3. 保存为新项目，或明确替换已有项目的数据版本。
4. 打开项目并生成课表；需要自动成班时，先填写班额与候选数量。
5. 在运行历史中查看课表，将满意的结果采用为独立方案。
6. 打开方案，选择需要的课表对象，导出 Excel 或 CSV；操作方法见 [课表导出指南](guide/exporting.md)。

导入检查用于发现明显的数据和资源矛盾，通过检查后仍需实际排课。详细格式和准备方法见 [数据导入指南](guide/importing.md)。

## 从源码运行

目前的桌面开发构建支持 **macOS 26 或更新版本、Apple Silicon**。需要 Rust 1.88.0、Node.js 24.20.0、CMake、Protobuf 编译器以及仓库锁定的 OR-Tools 开发包。

```sh
git clone https://github.com/FrankFu916/bell-scheduler.git
cd bell-scheduler
make frontend-install
```

按 [开发指南](guide/development.md) 准备 OR-Tools 后，构建应用：

```sh
make desktop-bundle
```

应用位于 `target/rust-1.88.0/debug/bundle/macos/排课助手 · Bell.app`。这是本地开发构建，尚未经过 Developer ID 签名和公证。

项目也提供 CLI，便于批量导入、排课和导出：

```sh
cargo run --locked -p class-schedule-cli -- --help
```

## 当前范围

Bell 仍在开发中，请先使用学校数据的副本评估工作流程。

- 导入支持 CSV 和 `.xlsx`，暂不支持 `.xls`、`.xlsm`、公式、合并单元格或自动猜测列名。
- 桌面可查看运行与方案课表、采用和复制方案；手动调课、锁定界面、继续优化和约束变更后的修复尚未开放。
- 桌面与 CLI 可导出所选方案对象的 Excel／CSV；CLI 还可导出运行 JSON 和自动成班名单。批量导出所有对象，以及直接 PDF、HTML、ICS 导出尚未提供。
- 当前没有 Windows、Linux 安装包，也未承诺大规模学校数据的求解速度。
- 目前只分发源码。原生依赖的二进制分发状态见 [第三方软件声明](THIRD_PARTY_LICENSES.md)。

## 参与开发

欢迎提交问题反馈和改进。构建方法、目录结构及测试命令见 [开发指南](guide/development.md)。

报告导入或排课问题时，请提供文件格式、操作步骤和错误代码，并使用去除学生及教师个人信息的最小示例。请勿将真实学校数据库、名单或账户凭据提交到公开仓库。

业务规则由 Rust application/domain 层维护，前端只负责交互。修改排课行为时，应保留独立校验、完整事务和版本冲突检查。
