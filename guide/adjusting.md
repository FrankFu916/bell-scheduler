# 调课与锁定

Bell 可以调整已经采用的方案。每次调整先检查整份课表，展示冲突和品质变化，再由你确认保存。预览本身不会修改数据；原始排课运行也会保留。

如果希望同时保留调整前后的两套安排，先打开方案，填写副本名称并点击 **创建独立副本**，然后在副本中调课。副本会保留当前课程安排和用户锁，之后可以分别调整。

## 移动课程

1. 在方案列表中点击 **打开并复核**，选择行政班、教师、学生等查看方式及对象。
2. 点击周课表中的课程，或在课程清单中点击 **查看**。课次详情会显示时间、授课对象、教师和教室。
3. 点击 **选择此课调课 / 锁定**，在“操作”中选择 **移动课程**。
4. 选择目标起点。如需固定调整后的安排，勾选 **移动后锁定此安排**。
5. 点击 **预览调整与冲突**，核对原时间、目标时间和整份课表的品质变化。
6. 全部硬性检查通过后，点击 **确认提交 · 保存新修订**。保存成功后，课表会重新读取并显示新版本。

这些操作可以使用键盘完成，无需拖动课程。移动只改变起点，教师、教室和连堂长度保持原安排；连堂是否跨越午休、教师是否可用、学生是否与其他课程冲突等，都由完整检查决定。目标课节在当前视图中看起来空闲，并不意味着一定可以调入。

## 交换两课起点

先选择第一课调课，再打开另一课次详情，点击 **与待调课程交换**。可以切换查看方式或对象寻找第二课，第一课的选择会保留。

检查面板会列出两课，再点击 **预览调整与冲突**。两课同时交换起点后检查，双方各自的教师、教室和连堂长度不变。只有整份课表满足所有硬性要求，才可以确认保存。

## 锁定与解锁

在“操作”中选择 **锁定当前安排**，预览并确认后，该课会显示“用户锁定”。锁定包含当前起点、教师和教室；想再次移动它，需要先选择 **解除用户锁**，预览并保存解锁。

课程还可能显示“来源固定”：这是导入数据规定的固定安排，不能通过解除用户锁移除。重复锁定，或选择与当前相同且不改变锁状态的安排，会显示“安排没有变化”，不会创建新版本。

## 如何处理预览结果

- **全部硬性检查通过**：核对调整影响后可以保存。品质代价越低越好；合法调整也可能使品质变差，是否接受由你决定。
- **存在硬性冲突**：查看涉及的课程、时间和具体问题，修改目标或交换对象后重新预览。有冲突的调整不能保存。
- **安排没有变化**：当前操作没有需要保存的变化，可重新选择操作或结束本次选择。

冲突检查覆盖整份课表，包括当前视图或页面之外的课程。问题较多时，界面会明确说明只展示了部分详情；未展示的问题仍参与检查。

改变目标、操作或交换对象后，需要重新预览。确认保存时 Bell 还会再次核对版本和全部安排要求；若其他操作已更新方案，请重新打开后再调整。

## 保存、重新打开与导出

每次有效调整都会增加方案和课表版本，旧版本数据仍保存在项目中。当前界面没有一键撤销或历史版本恢复功能，需要保留另一套安排时请使用独立副本。

如果已经显示“调课已保存”，随后重新打开失败，保存结果仍然有效。使用 **重试打开已保存修订**，或从方案列表重新打开核对；恢复读取前，旧课表的编辑与导出会暂停。若提示“提交结果未确认”，也应先重新打开核对，避免重复提交。

重新打开、复制和导出都会读取实际调整后的安排。导出方法见 [课表导出指南](exporting.md)。原运行课表可以继续在运行历史中单独查看。

项目重新导入数据后，旧方案仍可以查看、预览和导出，但不能继续提交调课或创建副本。请基于当前项目数据生成并采用新方案。

## 使用 CLI

CLI 与桌面调用相同的预览和提交用例：

```sh
target/rust-1.88.0/debug/class-schedule-cli preview-scenario-edit --help
target/rust-1.88.0/debug/class-schedule-cli commit-scenario-edit --help
```

两条命令都要求数据库路径、方案 ID、预期方案版本、预期课表版本和单个操作。支持 `move`、`swap-starts`、`lock-current`、`unlock`；活动 ID 和目标课节的稳定 ID 可从 `scenario-timetable` 返回的课程和周格读取。

预览返回变更、完整校验结果、品质比较和当前方案信息。提交必须携带相同操作，以及预览返回的 `scenario_payload_hash` 和 `timetable_payload_hash`，分别传给 `--expected-scenario-payload-hash` 和 `--expected-timetable-payload-hash`。不要自行生成或复用其他版本的摘要。构建和数据库操作见 [开发指南](development.md)。
