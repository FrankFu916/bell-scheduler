# 准备数据并导入项目

Bell 接受 UTF-8 CSV 和 `.xlsx` 工作簿。先准备学生、选科、课程及资源数据，在桌面应用中检查，确认无误后保存为本机项目，再开始排课。导入成功并不表示已经生成课表。

## 1. 选择学校的数据准备方式

| 方式 | 适用情况 | 需要准备的教学班数据 |
| --- | --- | --- |
| **A · 学校已成班** | 学校已确定每门选考课的教学班及学生名单 | 提供教学班表和教学班成员关系表；每位学生的每门选考科目都必须对应一个教学班 |
| **B · 自动成班** | 已收齐学生选科，尚未确定教学班 | 提供原始选科及课程、教师、教室信息；不要同时导入已有教学班及成员关系 |

两种方式都要提供学生选科关系，当前项目保存要求每位学生恰好选择 **3 门不同科目**。选科表只填写选考科目；语文、数学、英语等行政班课程由课程计划安排。

B 方式在导入检查时会使用所填班额策略生成临时候选，以检查数据是否存在明显矛盾。保存的仍是原始选科，不会把某个临时候选自动确认为正式教学班。保存后，每次排课前仍须明确班额及候选数量。

## 2. 按标准表结构准备数据

在应用中展开“**查看标准列名与可选表**”，可查看每张表的必需列和可选列。下表链接到仓库中的合成示例 CSV；打开文件后，第一行就是该表的标准列名，后续行展示填写方式。

| 数据表 | 标准文件名与示例 | 何时提供 |
| --- | --- | --- |
| 学生 | [students.csv](../fixtures/small/students.csv) | A、B 均必需：学生代码、姓名、所属行政班 |
| 行政班 | [administrative_classes.csv](../fixtures/small/administrative_classes.csv) | A、B 均必需：行政班代码、名称、年级、主教室 |
| 学生选科关系 | [student_subject_choices.csv](../fixtures/small/student_subject_choices.csv) | A、B 均必需：每行一位学生的一门选考科目 |
| 教师 | [teachers.csv](../fixtures/small/teachers.csv) | A、B 均必需：教师代码与姓名 |
| 教室 | [rooms.csv](../fixtures/small/rooms.csv) | A、B 均必需：教室代码、名称、楼栋、容量及可选设施标记 |
| 课程计划 | [course_plans.csv](../fixtures/small/course_plans.csv) | A、B 均必需：年级、学科、授课对象、周课时、连堂及资源要求 |
| 教学班 | [teaching_sections.csv](../fixtures/small/teaching_sections.csv) | A 方式必需：各选考教学班的班额、教师与教室策略 |
| 教学班成员关系 | [section_enrollments.csv](../fixtures/small/section_enrollments.csv) | A 方式必需：每行一位学生与一个教学班的对应关系 |
| 教师不可用时间 | [teacher_unavailability.csv](../fixtures/small/teacher_unavailability.csv) | 按需：教师不能授课的星期与节次 |
| 实际开课资源配置 | [course_offerings.csv](../fixtures/small/course_offerings.csv) | 按需：为具体行政班或教学班指定授课教师，或覆盖教室安排 |
| 固定活动 | [fixed_activities.csv](../fixtures/small/fixed_activities.csv) | 按需：将某次课程固定到指定时间、教师和教室 |

可以复制这些 CSV 的表头来制作自己的文件，也可以将表头与数据分别放入 Excel 工作表。示例中的学生、教师和学校代码都是合成数据，应替换为学校自己的完整数据。

### 列名与单元格

第一行直接填写标准列名，不要在上方添加标题、学校名称或说明行。列名使用示例中的英文拼写，例如 `student_code`，不能改成“学号”。应用支持文件和工作表对应到数据表，目前没有列名对应界面。

列的顺序可以调整，但必需列不能缺少；重复列名、未识别的附加列会被拒绝。没有使用的可选列可以不提供。**必需列名不等于每个单元格都必须有值**：例如没有专用设施要求时，`required_room_features` 这一列仍须保留，内容可以为空；不适用的教室候选列也应按所选策略留空。

学生表示例：

```csv
student_code,name,administrative_class_code
S001,学生001,AC01
```

同一位学生的选科应分为三行，而不是在一个单元格中填写三科：

```csv
student_code,subject_code
S001,physics
S001,chemistry
S001,biology
```

这些代码必须同时在相关表中存在。仅复制上面的几行，不能组成可独立导入的完整项目。

### 表与表之间如何对应

Bell 使用代码关联数据，不依靠姓名猜测对应关系。请保持代码及其大小写一致：

- 学生的 `administrative_class_code` 对应行政班表；行政班的 `home_room_code` 对应教室表。
- 选科表的 `student_code` 对应学生表，`subject_code` 对应课程计划中的学科代码。重复的“学生＋学科”关系不允许导入。
- A 方式的 `section_code` 对应教学班表。学生必须属于该教学班的年级，并已选择该班学科；同一学生同一学科不能进入两个教学班，也不能漏分班。
- `teacher_codes`、教室候选及固定活动中的教师、教室代码，都必须引用已提供的资源。
- `course_plan_code` 对应课程计划；`audience_kind` 为 `administrative_class` 时，`audience_code` 填行政班代码；为 `teaching_section` 时，填教学班代码。

B 方式没有已有教学班，因此不要在实际开课资源配置或固定活动中引用旧教学班代码。可以保留引用有效行政班的配置。若从完整的 A 示例开始练习 B 方式，先复制六张核心表和教师不可用时间表，不添加教学班、成员关系、实际开课资源配置和固定活动这四张表，再按需要补充适合原始选科数据的配置。

### 课时、班额和资源要求

`weekly_periods` 表示每周课时总数，`meeting_pattern` 表示各次上课的连续节数。例如 `weekly_periods=3`、`meeting_pattern=2;1` 表示一次两节连堂加一次单节课；各次节数之和必须等于周课时。`max_periods_per_day` 限制每天最多安排的课时，`min_days_between` 控制不同次上课的间隔，`may_cross_breaks=false` 表示连堂不能跨越设置的午休分界。

当前桌面导入日历为周一至周五。请在“每日课时”和“午休前最后一节”中填写学校安排。教师不可用时间、固定活动的 `period` 从 1 开始，必须落在此日历内；`day` 可按示例填写“周一”等文本。

班额满足“最小班额 ≤ 目标班额 ≤ 最大班额”。A 方式按成员关系表计算实际人数，不能低于教学班最小班额或超过最大班额。B 方式要求最小班额大于 0；若某科选科人数无法在给定范围内分班，检查会拒绝该策略。目标班额是成班目标，并不要求每班人数都完全相等。

教室 `capacity` 必须为正整数。实际授课人数不能超过教室容量；课程要求的设施也必须包含在教室的 `features` 中。增加最大班额不会增加教室容量，也不会取消实验室要求。学生冲突依据真实教学班成员关系检查，不能仅按行政班判断两节选考课是否可以同时安排。

`teacher_codes`、教室候选列表、`features` 和 `required_room_features` 使用分号分隔多个值，例如 `T01;T02`、`R01;R02`、`physics_lab;multimedia`。资源列表不要重复代码，也不要在末尾多加一个分号。

| 字段或策略 | 填写方式 |
| --- | --- |
| `teacher_assignment=fixed` | `teacher_codes` 恰好填写一个教师代码 |
| `teacher_assignment=candidates` | `teacher_codes` 填写非空候选列表；同一开课对象的各次课程使用选定的同一位教师 |
| `room_policy=admin_home_room` | 使用行政班主教室，其他教室列表留空；不能用于选考教学班 |
| `room_policy=fixed` | `room_candidates` 恰好一个教室，其他教室列表留空 |
| `room_policy=section_fixed` | `room_candidates` 为非空候选列表，选定后该教学班各次课程保持同一教室 |
| `room_policy=flexible` | `room_candidates` 为非空候选列表，各次课程可在允许的教室中安排 |
| `room_policy=preferred_fixed` | 填写非空 `preferred_rooms` 和 `fallback_rooms`，两组不能重叠，`room_candidates` 留空 |

固定活动用于锁定已有课程的一次上课，不会额外增加课程。`meeting_ordinal` 从 1 开始，对应 `meeting_pattern` 中的第几次；`duration` 必须与该次连续节数一致，教师与教室也必须符合课程的资源要求。

## 3. 选择 CSV 或 Excel 文件

### CSV

CSV 使用 UTF-8 编码，允许 UTF-8 BOM。若原文件使用其他编码，请在表格软件中另存为“CSV UTF-8”。分隔符为英文逗号；字段内容包含逗号或双引号时，需要按 CSV 格式正确引用，建议由表格软件导出。每行字段数应与表头一致。

标准文件名如 `students.csv` 可预填对应关系；中文文件名也可以使用，但添加后要在下拉框中明确选择数据表。例如“学生名单.csv”对应“学生”。

### Excel 工作簿

使用 `.xlsx`；旧版 `.xls` 请先另存为 `.xlsx`。每张工作表放一类数据，第一行使用同一套标准列名。工作表可以叫“学生”“行政班”“选科”等中文名称，添加后逐张选择对应数据表。标准英文工作表名如 `students` 可预填对应关系；这里对应的是整张表，并不会翻译或自动识别列名。

工作簿内的每张工作表都必须能对应一种数据表，没有“忽略此工作表”选项。请另存一份仅包含导入数据表的工作簿，移除其中的封面、统计图表页和填表说明页。

Excel 数据应整理为以下形式：

- 学生、教师、班级、教室等代码使用**文本单元格**，特别是带前导零的代码。名称、星期、列表和 `meeting_pattern` 也使用文本；即使单节课写作 `1`，`meeting_pattern` 仍应存为文本。
- 容量、课时、节次、班额等整数字段可以使用普通整数单元格；不要使用小数、负数或日期格式。
- 不接受公式，即使公式已经显示计算结果也不接受。请在导入副本中粘贴为值，并核对数据类型。
- 不接受合并单元格、错误单元格、日期或时长单元格，以及单元格内换行。请拆分合并单元格并补齐每行数据，去掉换行和汇总行。

一次可以多选、分批添加 CSV 和 XLSX，也可以混合两种格式。**同一数据表只能出现一次**：不能同时添加 `students.csv` 和另一张对应“学生”的工作表，也不能把学生表分散到多个文件后期待自动拼接。请先在导入副本中合并成一张完整表。

一次导入的原始文件总大小，以及工作簿展开为表格后的总数据量，分别限制为 32 MiB。单个工作簿最多 32 张工作表，每张最多 100,000 行、64 列；过大或结构异常的工作簿会被拒绝。删除导入副本中无用的空白区域和额外工作表，有助于减少文件体积。

## 4. 检查、保存，再排课

1. 在“导入设置”选择 A 或 B，填写日历参数，将“每生选科数”保持为 3。项目稳定键用于保持同一项目的数据身份，新建时填写，替换时沿用已保存值。B 方式还需填写本次检查使用的班额、候选数量和随机种子。
2. 点击“添加 CSV / Excel 工作簿”，确认每个文件及工作表的对应关系，补齐核心表和所选方式需要的数据。
3. 在“写入本机项目”中填写项目显示名称，明确选择“新建项目”或“替换当前项目的全部导入数据”；此时还未保存。已打开或保存过项目后再新建，须先点击“生成新项目 ID”。替换前先打开目标项目，或使用其 ID“重新读取项目 revision”，确认目标、当前数据版本及载入后的导入设置；重新读取后须再次选择“替换当前项目的全部导入数据”。
4. 点击“执行导入前审计”。检查只读取数据，不保存项目。按提示的数据表、工作表、行列及错误说明修改源文件；在文件列表中“移除”旧文件，再添加修改后的文件并重新检查。更改文件、对应关系、设置、保存方式或项目名称后，旧检查结果会清除，需要再次检查。
5. 点击“审计后新建本机项目”或“审计后替换当前项目”。保存会重新读取全部文件并完整检查，然后一次写入。替换是完整替换，不是只追加本次文件中的行；失败不会留下半个项目或增加数据版本。若版本已变化，重新读取项目、核对数据并再次检查，应用不会自动覆盖重试。
6. 保存成功后核对项目名称、ID、数据版本和成班状态。在“开始排课”设置求解时限等参数；B 方式再次明确本次排课的成班策略，然后点击“生成课表”。

“静态检查通过”表示未发现已检查的明显矛盾，不能保证一定排得出课表。生成结果还须通过独立的必需约束校验，才能打开课表；超时、取消或无法确定结果不会被当作可用课表。可以从“运行历史”打开并复核已保存的运行结果。

项目保存在当前电脑，保存后可从项目列表重新打开。导入文件和本机数据库可能包含学生、教师信息，请按学校的数据管理要求保管；当前本机数据库未提供静态加密。
